BEXO Premium Portfolio Standard

A detailed visual and technical contract for the Design & Creative portfolio template matching the BEXO navigation, profile renderer, responsive behavior, and platform handoff system.

Discipline: Design & Creative Four public routes Data-driven rendering Responsive + accessible

1. Product purpose

Every portfolio must answer four questions quickly: who is this person, what proves their capability, how can I contact them, and how can I hire them?

System rule New templates may change the visual language, but they must preserve the public-site contract. The BEXO renderer injects the normalized profile data into window.__BEXO_PROFILE__ and the navigation routes the same way across all templates.
Do not Add a second competing primary navigation, hard-code real user identity into production renderer files, or duplicate the platform Hire Me workflow inside a template.

3. Data contract

Production receives the normalized profile through window.__BEXO_PROFILE__. Local preview data is supplied by js/profile-data.js, but production works with injected data and does not depend on demo-only values.

{
  "user": {
    "name": "Alex Mercer",
    "email": "hello@alexmercer.design",
    "photoUrl": "assets/portrait.png",
    "resumeUrl": "assets/Alex_Mercer_Creative_Resume.pdf",
    "openToHire": true
  },
  "profile": {
    "handle": "alexmercer",
    "headline": "Creative Director & Designer",
    "careerGoal": "Crafting immersive visual identities and digital experiences.",
    "bio": "Short profile summary."
  }
}

4. Page-by-page implementation rules

Home

First viewport communicates identity and primary CTA without requiring a scroll on standard mobile devices.

Portfolio

Recommended order: About / identity → Skills → Experience → Education → Selected Work → Certificates → Achievements → Research. Empty sections hide automatically without gaps.

Contact

Direct mailto email link, openToHire driven badge, client validation for name/email/message, honeypot detection, submission to /api/profile/public/{handle}/contact, aria-live status.

Hire Me

Single platform handoff action to /hire-me/{handle} and fallback direct contact links.

5. Acceptance checklist

  • Home renders name, designation, photo, and View Portfolio action.
  • Resume CTA appears only with a valid resumeUrl.
  • Portfolio renders one, many, and zero items for each supported collection.
  • Empty sections hide without blank headings or gaps.
  • Contact reflects both openToHire: true and false.
  • Contact validation blocks invalid input and reports status accessibly.
  • Hire Me opens the platform route and has a fallback link.
  • Navigation works from every route with the correct active state.
  • Long names and headlines do not overflow.
  • 320px, 375px, 768px, and desktop widths have no horizontal overflow.
  • Keyboard navigation, focus states, skip link, and reduced motion work.
  • Console has no template runtime errors.
  • Production injection overrides local demo data.
